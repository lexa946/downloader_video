# Запуск сервиса

Серверу нужны Docker Compose, доступ к YouTube, Instagram, VK и отдельное S3-совместимое хранилище. В S3 создайте бакет для превью и разрешите публичное чтение объектов из него. Для S3 нужен действующий TLS-сертификат. Внешний HTTPS-прокси должен передавать запросы на `127.0.0.1:8084` и не буферизовать ответ `/api/get-video/`, поскольку через него передаются большие файлы.

1. Скопируйте `.env.production.example` в `.env.production` и заполните адреса S3, имя бакета и ключи. `S3_PUBLIC_URL` должен открываться браузером посетителя по HTTPS. Файл `.env.production` исключён из Git. Выдайте ему доступ только администратору сервера.
2. Проверьте, что публичное имя сайта соответствует canonical URL в шаблонах `app/frontend` и `sitemap.xml`. Сейчас там указан `https://downloader.pozharsite.ru`.
3. Настройте DNS и HTTPS-прокси. Для передачи cookie сайт должен открываться через HTTPS. Прокси должен передавать заголовки `Host` и `X-Forwarded-Proto`.
4. Запустите стек из корня проекта.

```sh
docker compose --env-file .env.production -f docker-compose.yaml config --quiet
docker compose --env-file .env.production -f docker-compose.yaml up -d --build --wait
docker compose --env-file .env.production -f docker-compose.yaml ps
```

Если при запуске появляется `ValidationError` с отсутствующими `FFMPEG_PATH`, `S3_*` и `REDIS_*`, контейнер не получил файл настроек. Запускайте команды из каталога с `docker-compose.yaml` и `.env.production`. Проверьте наличие всех ключей из `.env.production.example`. `--env-file` передаёт переменные в Compose, а строка `env_file` в `docker-compose.yaml` передаёт их контейнерам. После исправления пересоздайте веб-сервис и воркер командой `docker compose --env-file .env.production -f docker-compose.yaml up -d --build --force-recreate --wait`. Не публикуйте вывод `docker compose config` без `--quiet`, поскольку в нём видны секреты.

Redis доступен только сервисам Compose. Сайт слушает `127.0.0.1:8084`, либо порт `WEB_PORT` из `.env.production`. Контейнеры веб-сервиса и воркера используют общий том `downloads`. Данные Redis находятся в томе `redis_data`. Не удаляйте эти тома при обновлении.

После запуска проверьте главную страницу через публичный HTTPS-адрес. Откажитесь от cookie и убедитесь, что API скачивания возвращает `403`. Затем примите cookie, загрузите короткое видео с каждой площадки, дождитесь статуса готовности и сохраните файл. Проверьте декодирование файла плеером. Рабочее состояние и ошибки видны в логах.

```sh
docker compose --env-file .env.production -f docker-compose.yaml logs --tail=100 downloader_video worker redis
```

Для обновления сохраните копию `.env.production` и томов `downloads`, `redis_data`, затем повторите `up -d --build --wait`. Готовые файлы удаляются после передачи пользователю. Файлы, которые не забрали, удаляет ежедневная задача после `CLEANUP_RETENTION_HOURS` часов. Оцените доступный диск с учётом числа одновременных загрузок и размера больших видео. Настройте мониторинг свободного места, здоровья контейнеров и времени загрузки.

Установите `WORKER_MAX_JOBS` исходя из пропускной способности сервера и канала. Каждая задача YouTube может открывать до четырёх соединений для видео. При нескольких воркерах все они должны разделять Redis и том `downloads`. Перед увеличением числа воркеров проверьте диск, сеть и время получения файла на ожидаемой нагрузке.
